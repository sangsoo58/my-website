# PHASE 3 — Duplication-reduced Manuscript Integration Rules

Status: **ACTIVE EDITORIAL RULE**

## 원칙

Expanded Edition의 “82 CASE”는 82개의 서로 다른 기업/사업장을 의미하지 않는다. 일부는 하나의 대형 프로젝트를 분석질문별로 세분화한 Case다.

따라서 동일 프로젝트에서 반복되는 다음 요소는 대표 CASE 한 곳에만 충분히 설명한다.

- 프로젝트 개요
- 대상 사업장 수
- 전체 에너지비용
- Project-level 총 절감액
- 공통 Baseline
- 공통 플랫폼 Architecture
- 동일 PUE / UPI 표
- 동일 설비목록

Companion/Sub-case에는 다음만 남긴다.

- 해당 CASE의 독립 질문
- 해당 설비/운전상태
- 해당 Test·Benchmark·Scenario
- 그 CASE의 Evidence Boundary
- 대표 CASE와 다른 Consultant's Point

## Cross-reference 문구 예시

- “프로젝트 전체 배경과 성과 Portfolio는 CASE11 참조.”
- “다중 IDC 전체 개선 Story는 CASE38 참조.”
- “IPOS 전체 Architecture는 CASE39 참조.”
- “발전소 전체 Auxiliary Power 진단은 CASE28 참조.”

Cross-reference는 독자의 반복 읽기를 줄이기 위한 것이며 CASE ID를 삭제하기 위한 것이 아니다.

## Project-level Result 보호

동일 프로젝트의 총액은 대표 Umbrella CASE에서만 총괄한다.

Sub-case에서 사용 가능한 것은:
- Action-level Test 결과
- 해당 KPI 변화
- 해당 설비의 직접 검증값
- 명확히 분리된 Potential

합산 금지:
- Umbrella 총액 + Sub-case 동일 총액
- Program-level 27% + 개별 조치 절감률을 독립성과로 중복합산
- PUE 목표치와 세부 냉방 대안 예상효과의 단순합

## Editing target

목표는 CASE 수를 줄이는 것이 아니라:
- 중복 문단 감소
- 같은 표·그림 반복 감소
- 분석질문의 차별성 강화
- Source provenance 명확화
- 책 전체 분량 관리
이다.
